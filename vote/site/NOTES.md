# Verna 评委站前端说明

## 设计思路

- **气质与视觉**：参考 Linear、Stripe Press 与 Anthropic 的编辑部排版克制感，以“校对红（朱批）”作为唯一强调色，同时适配浅色（温润纸白 `#f9f8f5`）与深色（深炭黑 `#0b0b0d`）系统外观，确保高对比度且无渐变彩虹或营销装饰。
- **双模式节奏**：
  - 首页（`#/`）采用非对称双栏编辑部网格与细分割线；首屏使用轻量级 Canvas 校准网格与缓慢漂移的校对十字标（滚出视口、切换标签页、进入评审页或开启 `prefers-reduced-motion` 时自动暂停）；“问题”板块将两处例句做成可点击切换/自动演示的排版标本（划除动效 + 压缩展开动效）。
  - 评审界面（`#/review`）完全移除背景动效与光晕，专注连续阅读：正文字号 17px、行高 1.9、每栏约 30 个汉字（不超过 36 字），原文卡片与候选卡片以底色区分，选中后仅给边框、徽标与对勾的克制反馈，并降低另一栏不透明度。
- **兼容性**：零外部资源，纯系统字体栈（不含 Windows SimSun），ES2017 语法，不使用 `color-mix()` 或 `:has()`，复制链接提供 `execCommand` 兜底，键盘快捷键已屏蔽中文输入法合成期（`isComposing` / `keyCode === 229`）和组合键。

## 文件结构

- `site/index.html`：单页 HTML 结构（首页 6 个板块 + 评审界面 + 底部固定投票栏）。
- `site/style.css`：浅色/深色主题变量、响应式排版、动效及 `prefers-reduced-motion` 规则。
- `site/app.js`：hash 路由（`#/`、`#/review`、`#/submit`）、`fetchItems()` / `submitVote(record)` 接口边界与离线补发队列、评审交互逻辑、投稿表单、字级 LCS 标字、Hero Canvas 与例句标本控制。
- `site/items.json`：从 `proto/items.json` 复制的题库数据。
- `site/NOTES.md`：本说明与核对结果。

资源总计约 84 KB（`index.html` + `style.css` + `app.js` + `items.json`，不含本文件），远小于 200 KB 上限。

## 没能验证或拿不准的地方

1. **实机与无头浏览器渲染**：没有微信内置浏览器和真机，未做微信内实测。本轮用 headless Chromium 141 实际跑过桌面与 390px/360px 布局，以及取题、投票、改选、跳过、结束页、投稿、离线补发和 `items.json` 兜底的完整交互；360px 无横向滚动（`scrollWidth` = 360）。
2. **沿用原型但未在文案清单逐字写出的极短功能词**：
   - 原文卡片折叠按钮沿用原型的 `收起` / `展开`（对应功能要求“原文卡片可以收起和展开”）。
   - 原文与 A/B 卡片右上角沿用原型的字数提示 `N 字`（如 `215 字`），题材标签显示 `items.json` 里的 `genre` 字段。
3. **跳过交互**：原型点击跳过时会弹出 `"跳过了"` toast；为避免引入清单外中文提示，此处改为直接切换到下一题而不弹文字提示，并在已投票或队列只剩 1 题时隐藏 `跳过这题`。
4. **已评计数初始显示**：原型在 0 票时不显示计数；本实现固定显示 `已评 0 题`（投票后递增为 `已评 N 题`），避免顶栏跳动。

## 后端接入（2026-11-27 追加）

- 取题：`fetchItems()` 优先请求 `GET api/next?judge=…&n=5`（第一次带地址栏 `?from=`），网络错误或非 2xx 时退回读 `items.json`。本地队列剩不到 2 道时再取一批，取不到新题就进结束页；本地按 id 去重，避免接口重复返回队列里已有的题。
- 投票：`submitVote(record)` 先照旧写 localStorage，再 `POST api/vote`。投完立刻发一次，点“下一题”时带上理由和备注再发一次（服务端按同一评委同一题覆盖）。`改选` 调 `api/unvote`，`跳过` 调 `api/skip`。
- 失败请求存进 localStorage 的 `verna.proto.pending`，按顺序在本地下次成功请求后补发；同一题的待发投票会合并成最新一条，成功的请求会清掉该题过时的待发项。
- 新增 `#/submit` 投稿页（`POST api/submit`），错误提示按返回码对应：`too_short` / `too_long` / `duplicate` / `limit` / 其他。
- 入口：顶栏“投稿”、首页“你可以做什么”末尾的“投稿原文”、评审结束页的“投稿原文”。
- 没有改动任何已有页面文案；新增中文只来自任务书给的“投稿”“投稿原文”和投稿页那份清单。

## 追加改动：三个选项（2026-11-27）

- 评审选项从四个改为三个：`A 更好` / `原文更好` / `B 更好`，中间的“原文更好”用次要按钮样式；手机上三个按钮一行排开。
- 键盘改为 `←` / `→` / `↓` / `Enter`，去掉 `X`。
- 投票记录和后端请求里 `choice` 用 `a` / `b` / `src`；选“原文更好”时理由只有一组“两份改写的问题”，选项用 `BAD`。
- 删掉 `EVEN` 数组、“差不多”“都不行”的按钮、提示、键盘分支和相关样式。
